# TASKS.md — shared task ledger

Coordination rules: `AGENTS.md` → *Task ownership and multi-agent coordination*. In short:

- The repository owner or designated orchestrator assigns/confirms owner, reviewer, branch and scope before implementation starts; this ledger then records the authoritative assignment.
- This file is not a real-time lock across worktrees. Do not self-assign overlapping work; ask first.
- Scopes of `in-progress`, `in-review` and `blocked` tasks stay reserved until explicitly released.
- Edit only your own task's entry. Ledger updates for your task are always in scope.
- Placeholders for approved roadmap milestones are allowed (status `proposed`, planning-only scope). Do not add speculative implementation tasks.

Status values: `proposed` · `ready` · `in-progress` · `in-review` · `blocked` · `done` · `cancelled`.

No placement eligibility is supplied (none is verified), so reserve/taxi placement stays unknown. HTTP status: evaluated/blocked/withheld 200; invalid/unsupported 422 (with a trade-1 body); envelope errors 400/413/415; provider errors via `providerErrorResponse` (ESPN 422); load failures 502 with a generic message; incomplete internal state 422. Responses are the TradeEvaluation only, `no-store`. Nothing is persisted and nothing is written to a provider. `app/api/trade/route.js` is POST only. Team A defaults to the resolved or selected roster only (spectators choose both teams). The same team is disabled in the other selector. Players are listed by compartment (Starter/Bench/IR/Taxi) as 48 px checkbox rows with Remove/Clear chips. At most two per side. K/DEF/IDP-only players and players whose model is `supported: false` are disabled with the reason shown. Analyze is disabled until the proposal is valid; loading, route-error and stale-response states are handled. `lib/trade-loader.js` uses a generation counter and abort, and shows a result only for the same proposal key and snapshot basis. `app/components/TradeResult.js` shows status, horizon (Next game), conditional legality, "Market value: Not modeled", issues and limitations.
