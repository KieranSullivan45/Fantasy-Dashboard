# Weekly decision support — v0.3

`/api/snapshot` retains schema **0.2**, unchanged. The dashboard still loads that endpoint independently, so failed enrichment cannot remove league state or the actual matchup view.

`/api/decision-support?league=<configured-id>` returns schema **0.3** for the current league week. Optional `season` and `week` must match that scope; historical/future requests return 409 and invalid parameters return 400. Core Sleeper failure returns 502. Optional-source failure returns a partial response with null metrics and explicit source statuses. No external API keys are required.

## Layers and contracts

- `lib/sources/`: raw source adapters, bounded fetch/CSV parsing, short in-memory caches, normalized import interfaces for future rankings/projections/ownership.
- `lib/normalize/`: explicit GSIS-to-Sleeper mapping and league scoring. Ambiguous IDs are excluded; no name guessing.
- `lib/decision/`: pure historical production, schedule, positional allowance, team-strength, player-value and waiver calculations.
- `app/components/`: actual matchup, context cards, recommendations, component explanations and source status. No provider HTTP logic in components.

The response includes `league`, `basis`, `my_roster_id`, `scoring`, `matchup`, `player_context`, `matchup_difficulty`, `team_strength`, `waivers`, `sources`, `coverage`, `partial`, and `warnings`. `basis` identifies the roster/scoring/week state; clients discard responses for a different basis or an older request. Refresh re-synchronizes the two endpoints.

The player dictionary covers every roster/matchup asset, the displayed available-player rows, and returned recommendation/limited-data candidates. All eligible players are evaluated before response truncation. Source record counts and excluded mappings are exposed. Raw aggregate offensive stats and game IDs remain in matchup `game_values`; the complete source URLs are retained as provenance.

`PlayerValueProfile` and `TeamStrengthProfile` separate historical PPG from future market values, projections and dynasty values (all null). A historical lineup assignment respects FLEX/SUPER_FLEX eligibility and never assigns one player twice. IR/taxi/out players are excluded from usable weekly depth. This is not a start/sit optimizer or a trade finder.

## Free sources and attribution

- [Sleeper documented API](https://docs.sleeper.com/): authoritative league state, actual points, weekly starters, and 24-hour adds. The app's existing player-cache and league-cache intervals remain in effect.
- [nflverse weekly statistics](https://github.com/nflverse/nflverse-data/releases/tag/stats_player): current-season CSV, cached in memory for one hour. Data include raw stat lines, not generic PPR substitutions.
- [nflverse schedules](https://github.com/nflverse/nfldata/blob/master/data/games.csv): five-minute request cache. Eastern kickoff times are converted to UTC with daylight-saving handling.
- [DynastyProcess player IDs](https://github.com/dynastyprocess/data): explicit GSIS/Sleeper crosswalk, daily request cache. This uses IDs only, not the scraped rankings feed.

nflverse data are attributed under their [dataset licensing guidance](https://github.com/nflverse/nflreadpy). Raw provider data remain separate from derived metrics. These memory caches are not durable history storage. No HTML scraping or paid source is used.

## Scoring and historical coverage

Historical metrics use prior regular-season weeks only, excluding the current incomplete week and postseason. They cover QB/RB/WR/TE/K; FB statistics normalize to RB. Supported rules include passing/rushing/receiving yards and touchdowns, receptions, positional reception bonuses (including TE premium), interceptions, two-point conversions, fumbles/lost fumbles, individual special-teams TDs, offensive fumble-recovery TDs, and the configured distance-bucket kicking rules.

**Known limitations:** individual special-teams forced fumbles (`st_ff`) and recoveries (`st_fum_rec`) cannot be isolated reliably from these weekly columns. These rules are reported explicitly as unsupported, and resulting historical totals/PPG are labeled **supported-rule / partial**, not exact league totals. D/ST and IDP historical scoring are not implemented; their league actuals still come from Sleeper. Other unmapped custom rules also appear in `unsupported_rules`; missing required stat columns produce null points rather than zero. Source stat corrections and rare special-teams scoring differences can therefore differ from finalized Sleeper history.

Season PPG and recent averages divide by recorded statistical appearances. Missing zero-action appearances cannot be certified as games played from this dataset, so DNPs/byes/absent rows are not invented as zero games. Recent history shows up to three recorded games. Usage trend requires four games and compares targets plus carries per game in the latest two versus the preceding two; it is not route participation or snap share.

Positional allowance sums opposing QB/RB/WR/TE points per defensive game. It includes true positional zeroes when other player statistics confirm the game dataset exists, but excludes entirely missing game datasets. Output includes expected/covered games, totals, per-game values, recent four-game values, raw offensive aggregates and sample sizes. Descending competition ranks are labeled “3rd-most WR points allowed per game”; ties share rank, and the number of measured defenses is shown. Small samples are flagged. This is not an opponent-adjusted predictive metric.

## Actuals, projections and schedule

Weekly matchups pair roster IDs using Sleeper matchup IDs and use the weekly starter order. Zero points and commissioner overrides are preserved. Only current-week totals are shown, not multi-week playoff aggregates.

Projections remain null. Schedules identify opponent/home-away/kickoff and count starters scheduled later, but do not claim live remaining-player counts. A passed kickoff is labeled as such; it is not interpreted as a confirmed final game. Unknown and unscheduled games remain distinct.

## Waiver model `production-v1`

This is an explainable historical heuristic, **not predicted points or a calibrated win probability**:

| Component | Weight |
| --- | ---: |
| Season positional PPG percentile | 35% |
| Recent positional production percentile | 25% |
| Usage change (targets + carries) | 10% |
| Positional matchup allowance | 15% |
| Improvement over weakest compatible historical lineup slot | 15% |

Components expose raw inputs, normalized scores, weights and contributions. External quality/upside are null, zero-weight extension points rather than invented rankings. Interest/add counts are displayed separately and never used as ownership or usage growth. Compare scores only within identical available-component groups. Missing weights are not redistributed; groups sort by evidence coverage, then score. A scored result requires season/recent history and at least 75% component coverage. Small samples and partial scoring are flagged. Injured/out, bye and kickoff-passed candidates are separated as limited/stash cases; they remain in the eligible holdings pool.

The entire v0.2-eligible pool is evaluated. Only afterward are the top 20 overall scored candidates and 20 limited examples returned. The UI can filter those returned candidates by position; this does not claim to provide the top 20 of each position. Unknown starter production does not count as a weak starter when computing team need.

## Optional data and deferred work

Rankings, projections, ownership percentages and ownership change stay null with source status `unsupported`. Import interfaces validate IDs, season/week, scoring profile, timestamps and units. Ranking consensus deduplicates source families so mirrors are not counted twice. There is no public upload route, licensed data export, provider registration, or ownership-history persistence in this release.

v0.4 preparation is limited to contracts: no trade finder, trade offers, market-value claims, paid providers or automated transactions. v0.3.1 candidates include historical zero-action participation coverage, rare special-teams reconciliation, model backtesting, richer role evidence, and per-position recommendation pagination.

## Validation

`pnpm test`, `pnpm build`, and `pnpm test:ui` are deterministic and do not need paid services. Browser tests use fixtures and include mobile layout, optional-source failure and league-switch races. `pnpm smoke:live` explicitly contacts the public sources and validates both configured leagues; set `SMOKE_BASE_URL` to test the deployed HTTP endpoints. No smoke-test data is written to files.
