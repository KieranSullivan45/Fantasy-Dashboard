## Proposed additive architecture

* Identity: provider → stable provider_user_id → season → league_id → optional roster_id. `lib/accounts` validates/discovers Sleeper users/leagues and centralizes season selection. Browser-local account selections are independent; no authentication is implied by a public Sleeper username. Direct league requests default to spectator unless an identity/roster is explicitly selected. Existing installation preferences move into data configuration, not business rules.
* Keep snapshot 0.2 and decision 0.3, adding optional identity queries and separate `/api/accounts` and `/api/chat/*` read-only routes. Fingerprints/caches include identity. No arbitrary upstream URLs. Historical leagues retain rosters/scoring but current-week forecasting remains unsupported rather than borrowing the current season.
* Immutable observation envelopes contain exact decision evidence, source timestamps/digests, identity, model/feature/implementation versions and record schema. Deterministic IDs exclude volatile fetch times and deduplicate unchanged evidence within a six-hour bucket; first captured timestamp is retained. Outcome records are separate joins with strictly post-observation games. No fabricated prospective results.
* Storage: in-memory and exclusive-create filesystem implementations; production durable Git archive on separate `data-archive` branch using the existing public repository and GitHub Actions built-in token. No new hosted account/secret, no writes on public GET requests, no Vercel filesystem persistence. Scheduled captures cover configured installation leagues only; friend browser selections remain local unless explicitly enrolled in deployment configuration. Gzip append-only batches and a bounded discovery index; no automatic deletion. Public league/player analytics only, no social-user identifiers. Document capacity/retention limits and migration before large scale.
* Precompute allowlisted nflverse PBP aggregates in an ingestion job. API requests fetch small season-specific aggregates; never full PBP. Persist source SHA, retrieval time, games/weeks, derivation version and play provenance. High-value metrics remain informational: do not populate previously missing calibrated feature inputs and thereby change football weights inadvertently.
* Pure `lib/signals` engine consumes as-of weekly evidence and independent market observations. Stable signal IDs, confidence/sample gates, source provenance and evidence power both UI and machine endpoints. Signals are informational/alert candidates, never hidden model-score boosts.
* Market layer: Sleeper 24h add counts + archived, comparable windows; missing top-100 entries stay unknown, never zero. Permitted aggregate-import contracts for Reddit/X, disabled live social adapters without approved access. No raw posts, handles, sentiment guesses, scraping or betting inputs.
* UI: functional account/season manager, bounded Signal Feed and evidence details. Machine endpoints project compact fields from the same decisions/signals; no separate scoring logic. History/status exposes what is actually archived and its capture time/scope.

## Signal formulas (signals-1)

All thresholds are deliberately conservative, interpretable **heuristics**, not calibrated predictive claims. No forecast weights change. Fractional shares below mean percentage-point differences, not relative percent growth. Role history uses unique same-team games from the requested season, week ≤ data_through_week and < decision week. Up to four games are used. Freshness requires at least two games, latest game at decision week−1 and a bounded gap (week span ≤ sample count). Four-game changes compare last-two mean minus first-two mean; two/three-game changes compare last minus first. No missing values are imputed.

| Type | Trigger |
| --- | --- |
| ROLE_EXPANSION | Snap change ≥.18 AND target change ≥.06 or carry change ≥.15 |
| ROLE_DECLINE | Snap change ≤−.18, independent of historical points |
| SNAP_SHARE_SPIKE | Change ≥.25 and latest share ≥.50 |
| TARGET_SHARE_SPIKE | Change ≥.08 and latest share ≥.18 |
| CARRY_SHARE_SPIKE | Change ≥.20 and latest share ≥.30 |
| BACKFIELD_SHIFT | RB eligibility, absolute carry-share change ≥.20 and some share ≥.30 |
| XFP_BREAKOUT | Matched-rule xFP change ≥3 and last-two mean ≥10 |
| OPPORTUNITY_OVER_RESULTS | Last-two xFP mean ≥10 and matched-rule FPOE mean ≤−4 |
| PRODUCTION_OVER_OPPORTUNITY | Last-two xFP mean ≥5 and FPOE mean ≥5 |
| ROLE_STABILITY | Four games, snap range ≤.08 and mean ≥.70 |
| HIGH_VALUE_OPPORTUNITY_CHANGE | At least two covered same-team games; latest at through-week; last−first absolute red-zone opportunity change ≥3, with either endpoint ≥4 |
| SCHEDULE_IMPROVEMENT / DECLINE | Current and at least two next-three scheduled opponent positional samples ≥4 games; future mean adjusted positional FP allowed minus current ≥3 or ≤−3 |
| MARKET_INTEREST_RISING / FALLING | Comparable archived 24h windows: delta ≥100 and ≥50%, or ≤−100 and ≤−50% |
| BUZZ_AND_DATA_CONFIRMATION | Rising attention AND ROLE_EXPANSION |
| HYPE_RISK | Rising attention, fresh flat snaps (absolute change <.08), mean snaps <.50, observed mean xFP <8 |
| QUIET_BREAKOUT | ROLE_EXPANSION and observed available-pool attention percentile ≤30; missing attention never qualifies |

Two games → low confidence; three/four → at most moderate. Fewer than four games carry a visible small-sample warning. Changed-team and current injury flags warn that prior role may not transfer and historical role is not current availability. Prior contribution is preserved as evidence, not secretly mixed into trend samples. Rookies/new roles are provisional under the same small-sample safeguards. No confidence percentages. Missing route participation, structured injury causality or approved social feed leaves route/injury-opportunity/social-only buzz signals unsupported.

Signals expose deterministic ID, player/league/season/week, direction/severity, confidence/sample, raw evidence, source identifiers, generation/through-week, model version, explanation and warnings. Alert candidates are exposed, delivery is deferred. Cap5/player (combined market/role flags first) and100/feed (notable before contextual); total/omitted apply after the per-player cap. UI displays the same records as API, with no independent scoring rules.

## Observation schema and future evaluation

`observation-1` stores identity, exact capture time, source versions/digests, model/feature/revision, player/eligibility/status, StartValue/PickupValue/FootballValue, roster value, replacement/VOR, legal transaction and deltas, component scores, categories/explanations, xFP/FPOE, recent usage, high-value/matchup evidence, active signals, independent attention, sample/prior/confidence, scoring and warnings. `capture-1` batches these; `archive-index-1` discovers them; `market-1` preserves attention. No proprietary rank feed or raw social text is archived.

Future evaluation can compare as-of recommendations/signals with next1/3/4 games or ROS after matching player IDs and available-at dates. Questions include role persistence, opportunity/points gain, add/drop opportunity cost, start/sit accuracy and confidence cohorts. This release creates the immutable predictor/outcome boundaries; it does not invent prospective results or automatically retune weights. Archive selection is not a complete historical waiver-universe reconstruction.

## Rollout and future work

Initialize `data-archive` from the validated release once, publish `data/high-value` and captures, then enable the main workflow. Worker uses current main code with its exact SHA, never stale code from the archive checkout. Standard public Actions runners and built-in token avoid a new service/account. Failed upstream aggregate refresh preserves last-good data and its original through-week; observation warnings expose lag. Failed Git publication never force-pushes.

Before v0.4: accumulate prospective weeks, evaluate signal cohorts, review archive growth, decide permitted market-value source and private-user storage if needed. Trade generation, notifications, Reddit approval, X paid access, route/end-zone metrics and full prospective calibration remain outside this release.
