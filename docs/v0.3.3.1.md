# v0.3.3.1 — Navigation shell

This release reorganizes the UI only. Snapshot 0.2, decision-support 0.3, assistant endpoints, calibrated weights, signal thresholds, add/drop safeguards, archive semantics and ingestion remain unchanged.

## Routes and content

`/` and `/dashboard` redirect to `/dashboard/home`. Each destination is independently reloadable and bookmarkable.

| Route under `/dashboard` | Content |
| --- | --- |
| home | Actual matchup summary, first existing waiver recommendation, lineup link, top three existing signals, warnings and quick links. No new ranking logic. |
| waivers | Recommendations with existing category/position filters; add/drop and roster deltas; expandable evidence. All Available is paged separately. |
| lineup | My roster including bench/IR/taxi, actual opponent matchup, alternatives ordered by existing StartValue with evidence. No new start/sit model. |
| signals | Existing engine records, grouped UI filters and 20-row pages; confidence, samples, through-week and evidence preserved. |
| league | Standings, transactions, individual team rosters/strength, format/scoring disclosures. |
| players | Search/filter known rostered and returned available players, 15 results per page, detail links using `?player=ID`. |
| more | League/Players links, expanded account management, history/assistant JSON links, model/source diagnostics. |

## Persistent shell and state

The dashboard layout owns account/league/season selection, snapshot and decision loaders, and view filters. Route changes preserve loaded data and filters without repeating API requests. Existing cancellation, selection-key and decision-basis checks prevent stale cross-league results. League/season discovery preserves the route; unsupported filters fall back safely. Missing selected player IDs show an unavailable message instead of another league's stale evidence.

Account selections retain the existing browser-local persistence. Search, filters and local sub-tabs persist across client navigation, but reset on a full reload. Player detail URLs survive reloads. No new storage semantics or server persistence were added.

## Responsive navigation and accessibility

Below 768px the fixed bottom navigation contains Home, Waivers, Lineup, Signals and More. League and Players are two taps away via More. At 768px and above a persistent sidebar exposes all seven destinations. League and season controls remain compact and accessible on every route.

Bottom padding reserves the 64px navigation height, 24px clearance and `env(safe-area-inset-bottom)`. The viewport uses `viewport-fit=cover`. Normal document scrolling is preserved. Deep tables/JSON retain their existing bounded overflow behavior.

Semantic navigation links use visible active styles and `aria-current`. A skip link, visible focus rings, route-change main-content focus, labeled controls, 44px control targets and text direction/confidence labels support keyboard and screen-reader use. Safe-area CSS is tested; physical iOS hardware has not been tested.

## Performance and compatibility

Next route chunks split the major views. Navigation prefetch is disabled for shell links. Only the current view mounts; Home does not render full feeds/rosters. Player results are bounded at 15 and signals at 20. The shared existing APIs still return full league data: this release reduces rendered content, not server payload size.

Local build First Load JS: Home 112kB; League/Lineup/Players/Waivers 115–117kB; Signals/More 111–112kB; shared 102kB. Baseline single dashboard was about 114kB. The main benefit is organization and bounded DOM, not a large bundle reduction.

Validation includes the full 83 unit/API tests and 18 browser tests, covering race safety, dual positions, injured stashes, calibrated evidence, friend onboarding, spectator selection, future seasons, direct routes, history, refresh, desktop navigation, filter persistence, one shared fetch per selection, player deep links, assistant JSON validation, and all seven views at 320/375/390/414px without overflow or covered final content. Live validation and deployment results are reported separately for the exact released revision.
