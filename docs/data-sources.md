nflverse distributes public data under the applicable project/source license; the data repository documents CC-BY-4.0 attribution. Preserve attribution and consult upstream notices before broader redistribution. This app stores derived football aggregates with provenance, not proprietary rankings. Upstream corrections are permitted in **new** aggregates/observations; old capture files never change.

## Reproducible high-value derivation

Before decision week W, accept only regular-season rows with week < W, unique (game_id, play_id), valid yardline_100 in [0,20]. Exclude no-play, kneels, spikes and two-point tries. Carries require rush_attempt and rusher ID; targets require pass_attempt and receiver ID. Count red-zone carries/targets at ≤20, carries at ≤10/≤5, targets at ≤10. High-value opportunities = red-zone carries + targets. Share = player opportunities / all identified team opportunities in that game. Red-zone carry share uses team red-zone carries; goal-line carry share uses team carries at ≤5. These are play-location counts, not modeled scoring probabilities. End-zone targets remain unsupported.

Zero events are assigned only when the source fully processed the game and an existing statistical player-game record can be joined by GSIS/game ID. Missing/unmapped games stay unknown. Samples/through-week and source play IDs are retained. Normal requests load the small precomputed aggregate, never PBP. Bounds: 60MB compressed download, 350MB decoded CSV, 1MB logical row, 8MB served aggregate. Larger future sources must be explicitly reviewed rather than silently truncated.

## Durable archive and evaluation

`data-archive` branch stores `data/observations/{season}/{league}/{capture_id}.json.gz`, `data/index.json`, `data/high-value/{season}.json` and `data/market/{season}.json`. The worker runs on a 6-hour schedule, manual dispatch, and successful main CI. Git publishes one atomic commit. A single workflow concurrency group serializes writers; non-fast-forward pushes fail instead of overwriting data. The archive branch is excluded from application CI and Vercel deployment.

`observation-1` is a detached JSON copy. IDs hash canonical evidence plus a 6-hour time bucket, excluding volatile fetch/generation timestamps and nested IDs. Same evidence in the same bucket deduplicates; material changes or a new bucket produce new records. Exclusive-create captures never overwrite earlier bytes. An interrupted discovery-index update can be repaired from the original file. Local memory/filesystem stores support tests; the filesystem store refuses Vercel durability. Public GET endpoints never write.

The index retains the newest 1000 capture entries; immutable files remain reachable in the branch/Git history. No automatic record deletion. Market comparison index is 14 days, with original values preserved in captures. Archive growth must be monitored (projected hundreds of MB/year depending on scope); migrate to approved object storage before repository size becomes operationally costly. Public Git is suitable for this small public installation, not private multi-tenant data. New hosted storage/authorization is intentionally not required.

Schema migrations add a new version and reader; do not rewrite old captures. Future `outcome-1` joins select only games after observation time and with completed/available-at timestamps no later than evaluation time. Next-game/3-game/4-game/ROS outcome records remain separate from immutable predictors. No prospective performance is claimed before enough outcomes exist.

Scheduled capture scope is installation-configured leagues, stable account ID, all rostered and returned/signal decision contexts. The full eligible pool is scored but omitted contexts are **not** claimed archived; omission counts are stored. Friend selections are browser-local and not enrolled automatically. This bounded scope avoids a public write/ingestion endpoint and unlimited archive growth.
