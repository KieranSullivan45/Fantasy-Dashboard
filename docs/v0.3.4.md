# v0.3.4 — Provider boundary and limited ESPN support

## Audit before refactoring

Baseline: 3c7c25e. `lib/sleeper.js` already constructs the engine's snapshot shape, but `decision/build-context.js` imports its loader directly; `normalize/player-ids.js` and analytics join through sleeper_id. Snapshot/accounts/chat routes, decision cache keys, client loaders and installation defaults assume Sleeper. History observation construction hardcodes provider=sleeper. Matchups use a legacy normalized shape resembling Sleeper; scoring uses stable named coefficients originally adopted from Sleeper. These are compatibility vocabulary, not permission to reuse another provider's raw objects. Sleeper add interest is explicitly provider-specific and must not be synthesized for ESPN.

## Access decision

Research on 2026-09-24 found no supported third-party ESPN Fantasy API/OAuth contract. ESPN support documents public viewing, but Disney Terms section 2.B.x restricts automated extraction without written permission. Accordingly this release must NOT activate the undocumented web endpoint, collect cookies, or claim working private sync. The user explicitly authorized a safe limited mode if current access is unsuitable. Implement offline normalization of authorized/synthetic data, a browser-local import preview, and a disabled live provider with explicit capabilities/errors. No new hosted credential store. A future approved transport is injected behind the provider boundary, not added to UI/model code.

## Architecture plan

Provider registry → normalized snapshot/domain contracts → existing engine. Default provider remains Sleeper and legacy snapshot output remains byte-shape compatible. Provider identity enters cache keys, request routing and history filtering. The ESPN normalizer uses namespaced canonical IDs, explicit external crosswalks only, named scoring coefficients and explicit unsupported slots/rules. Core formulas and thresholds do not change. Legacy Sleeper numeric IDs remain compatibility identifiers; new canonical refs provide a migration path rather than destructively renaming existing IDs.

ESPN import preview stays in browser memory and is never uploaded, archived or exposed on public assistant routes. It is not a live connection or an analytics-parity claim. Normalized ESPN fixtures exercise the shared engine through an injected provider loader. GET endpoints report unsupported ESPN live access consistently, rather than returning fabricated league data. Private production activation requires permission plus a separately approved secure credential flow; adding cookies alone cannot enable it.

## Delivered boundary and limitations

`lib/providers` owns provider access, capabilities, identity adapters, normalized scoring/slots and optional provider attention. Decision construction requests a provider context rather than importing the Sleeper transport. The engine continues to consume the established normalized snapshot vocabulary, retaining legacy public IDs and scoring coefficient names for compatibility. `fantasyDomain` and `types.d.ts` document the additive canonical domain projection. This is deliberately not a destructive ID/schema migration.

Sleeper live account management is unchanged. ESPN is an authorized-file preview under More, not a second live connected account. No private authentication material is accepted. Unknown scoring, missing crosswalks and incomplete pools remain explicit. An injected offline ESPN provider can exercise the existing engine in tests; production ESPN analytics are unavailable until permitted transport, complete pool coverage and current-season verification exist.

No calibrated weights, signal thresholds, optimizer/add-drop policy, archive retention, snapshot schema or mobile navigation changes are included. Provider cache namespaces and archive partitions are additive; old Sleeper captures retain their paths and format.
